| 항목 | 최초 계획(v3) | 실제 구현 | 이유 |
|------|--------------|-----------|------|
| **영상 소스** | 영상 URL 입력 / 온라인 샘플(BigBuckBunny) | **로컬 폴더 `public/videos` 자동 스캔 → 목록 표시** | 구글 샘플 URL 403 차단. 사용자가 실제 mp4를 폴더에 넣어 테스트 |
| **영상 서빙** | (해당 없음) | **커스텀 Vite 미들웨어**: 파일명을 base64 ID로 감싸 스트리밍(HTTP range) | 파일명의 `#`·공백·이모지·대괄호가 `import.meta.glob`/정적서빙을 깨뜨림 |
| **핫스팟↔제품** | 핫스팟당 **제품 1개**(productUrl 등 단일 필드) | 핫스팟당 **제품 여러 개**(`products[]`) + **탭 UI** | 사용자 요청(한 장면에 여러 제품) |
| **제품 재사용** | (없음) | **제품 라이브러리(카탈로그)** + 우측 슬라이드 **드로어** | 사용자 요청(제품 정보 재사용) |
| **제품 필드** | url·설명·수수료·회원명 | + **image·price** 추가 | enrich 이미지·가격 표시용 |
| **시청 다중클릭** | (단일 이동) | 제품 여러 개면 **썸네일 팝업**에서 선택 | 다중 제품 UX |
| **Serper enrich 시점** | **2차**, Convex action에서 호출 | **구현2(지금)**, **Vite 개발 미들웨어**(`/api/serper`)에서 호출 | 조기 검증. Convex 전 단계 |
| **enrich 방식** | Serper만 | **① 링크 OG 추출(`/api/enrich`) + ② Serper 검색** 둘 다 | 사용자 요청. 단 **네이버·쿠팡은 안티봇으로 OG 차단** → KR몰은 Serper(구글 색인)로 우회 |
| **Serper 키 위치** | Convex action(서버) | 현재 **`.env.local`(SERPER_API_KEY)** + Vite 미들웨어(서버측) | 2차에 Convex action으로 이전 예정 |
| **Serper 검색어** | 제품명/URL | **제품명 필드**(비면 설명) | 핫스팟 제목 아님 — 제품명 사용 확정 |

> 유지된 것: React19+Vite+Zustand v5 / 좌표 레터박스 보정 / 수수료·회원명 내부용 / Convex·회원 auth는 2차 / JSON·localStorage 저장.

## 0. 개요 & 성격

영상을 올린 **회원(업로더)**이 영상 위 제품 위치에 **핫스팟**을 찍고, 각 핫스팟마다
**링크·자세한 설명·제품링크·수수료·회원명·기타 메타데이터**를 자유롭게 입력한다.
**시청자**가 영상을 보다 핫스팟을 클릭하면 회원이 지정한 목적지로 이동한다.

- **JoySpot(joy.it.kr) = 링크 목적지가 아니라 영상을 올리고 오버레이를 다는 플랫폼(호스트)**
- 링크 목적지는 회원이 핫스팟마다 자유 지정 (자사몰/제휴몰/제품 상세 등 어디든)
- **1차는 핵심 UX(좌표·클릭·편집) 검증 중심**, 데이터 구조는 처음부터 플랫폼용

## 1. 메모리 분할 (핵심 정의)

| 구분 | 내용 |
|------|------|
| **핵심 목표** | 영상 속 제품을 직접 클릭 → 회원이 지정한 링크로 연결 (플랫폼 비종속) |
| **1차 범위** | 영상 재생 + 핫스팟 표시/클릭 + 편집(드래그+폼) + 메타데이터 입력 |
| **차별점** | 정밀 위치 클릭(레터박스 보정) + 영상만으로 후처리 + 제품정보 자동 enrich |
| **수익 연결** | 링크는 회원 자유 지정. 수수료·회원명은 **기록용 메타데이터**(1차) |
| **성공 기준** | 모바일에서 제품 위 클릭이 자연스럽고, 링크가 정확히 이동 |
| **비종속성** | 데이터 구조를 깔끔히 유지해 2차(회원/정산)로 무변경 확장 |

## 2. 역할 분할

### 2-1. 서비스 등장 인물 (4 액터, v4.1 재정의)
| 역할 | 계정 | 소유/매핑 단위 | 하는 일 |
|------|------|----------------|---------|
| **플랫폼 운영자 (조이텍)** | operator | 전체 | 회원·영상·수수료·정산 관리 |
| **회원 업로더** | uploader | **영상 단위 소유** | 영상 등록, 핫스팟·제품 편집 |
| **회원 쇼핑몰 관계자** | mall | **제품(Tab) 단위 매핑** | 자기 제품 링크/수수료, 실적 조회 |
| **시청자 구매자** | 익명(계정X) | — | 시청·클릭·구매 |

**소유/매핑 규칙 (핵심):**
- **업로더 = 영상 단위**로 동일 (한 영상의 모든 핫스팟은 그 업로더 소유) → `videos.uploaderId`
- **쇼핑몰 관계자 = 제품(Tab) 단위**로 개별 매핑 (같은 핫스팟이라도 제품마다 다른 mall 회원 가능) → `products[].mallMemberId`
- 현재 `products[]` 구조가 제품별 개별 필드를 이미 가지므로 **제품별 매핑은 구조상 지원됨**. mall 회원 "참조화"만 추가.

### 2-2. 개발 역할 (기술)
| 역할 | 책임 | 스택 |
|------|------|------|
| 프론트엔드 | 플레이어·핫스팟 렌더·편집 UI | React 19 + Vite |
| 상태(메모리) | 플레이헤드·핫스팟·드래그 상태 | **Zustand v5** |
| 백엔드/DB | 영상·핫스팟·회원 영속화 | 현재 **localStorage(persist)** → **Convex**(2차) |
| 서버 API | 영상 스트리밍·enrich | **Vite 개발 미들웨어**(`/api/*`) → 2차 Convex 이전 |
| Enrich | 제품 정보 자동 채움 | **링크 OG + Serper API**(서버측, `.env.local`) |
| 개발 보조 | 최신 문서/기획/스킬 | **Context7 MCP · bkit(PDCA) · skills.sh** |

## 3. 기능정의서 (1차 MVP)

### 3-1. 사용자 시나리오
1. 회원이 영상을 `public/videos` 폴더에 넣으면 목록에 자동 표시된다. (2차: 업로드/URL)
2. 편집 모드에서 제품 구간에 핫스팟을 추가하고 드래그로 위치를 잡는다(숫자 미세조정 가능).
3. 핫스팟에 **제품을 여러 개** 붙이고, 제품마다 링크·설명·가격·수수료·회원명을 입력한다. (🔗 링크 OG / 🔎 Serper로 자동 채움, ⭐ 라이브러리 저장·재사용)
4. 시청 모드로 미리 확인한다.
5. 시청자가 제품 위를 클릭 → 제품 1개면 바로 이동, 여러 개면 썸네일 팝업에서 선택 후 이동.

### 3-2. 기능 목록
**A. 영상 재생** — HTML5 `<video>`, 기본 컨트롤, 반응형, 비율 유지(`object-fit: contain`)

**B. 핫스팟 표시** — 현재 시간대(start~end) 핫스팟만 표시 / 좌표는 **실제 렌더 영상 영역 기준 %**(레터박스 보정) / 항상 표시(반투명)+호버·터치 강조 / 모바일 최소 44px

**C. 핫스팟 클릭** — 지정 URL 새 탭 이동 / 클릭 시 일시정지(기본) / 이벤트 버블링 방지 / 이동 먼저 → 로그 나중(팝업차단 회피)

**D. 편집 UI** — 시청/편집 모드 토글 / 핫스팟 추가·삭제 / **드래그 위치 지정(pointer capture, 터치 지원)** / 숫자 미세조정 / start~end 설정(「현재」 버튼) / 색상·크기 / **제품 다중 관리(탭 UI)** — 제품별 폼(제품명·URL·설명·가격·수수료·회원명) + **enrich(🔗 링크 OG / 🔎 Serper)** + **⭐ 라이브러리 저장** / **📚 라이브러리 드로어**(우측 슬라이드)에서 재사용 / JSON 내보내기·불러오기 / **저장은 Convex 실시간**(제품별 mall 회원 드롭다운·클릭 카운트 포함)

**E. 데이터 구조 (플랫폼-레디, 구현 반영: 핫스팟당 제품 다중)**
```json
{
  "videoName": "product-clip.mp4",
  "hotspots": [{
    "id": "hs_001", "label": "가방 존",
    "x": 65, "y": 40, "start": 5.0, "end": 18.5,
    "pauseOnClick": true,
    "style": { "size": 34, "color": "rgba(255,80,80,0.78)" },
    "products": [
      {
        "pid": "p_...", "name": "빨간 크로스백",
        "url": "https://판매자몰/product/123",
        "image": "https://.../thumb.jpg",
        "description": "가을 신상 크로스백...",
        "price": "39,900원",
        "linkType": "affiliate",
        "commission": { "type": "percent", "value": 10 },
        "memberName": "홍길동"
      }
    ]
  }]
}
```
- 핫스팟은 위치·시간·스타일만, **제품은 `products[]` 배열**(다중 링크)
- 별도 **제품 라이브러리(catalog)**: `{ cid, name, url, image, description, price, linkType, commission, memberName }` — localStorage `joyspot-hotspots`에 함께 영속화
- 구버전 단일 링크 핫스팟은 로드 시 **자동 마이그레이션**(`products[]`로 변환, persist version 2)

**F. 1차 제외** — 회원가입/로그인 · 실제 구매/정산 추적 · 클릭 통계 대시보드 · 자동 물체 추적 · 파일 직접 업로드 · 결제 연동

## 4. 아키텍처

```
React (Vite) — SPA, 시청/편집 모드 토글
 ├─ Zustand store (in-memory + persist:localStorage)
 │    videos · selectedVideoUrl · mode · hotspotsByVideo · catalog · playhead
 │    persist(version 2): hotspotsByVideo + catalog 만 영속화
 ├─ Viewer
 │    <video> + Overlay(absolute, pointer-events:none) + coords.js(레터박스 보정)
 │    ├ 시청: Hotspot → 제품1개 window.open / 다중이면 썸네일 팝업
 │    ├ 편집: EditableHotspot → 드래그(pointer capture)로 x/y 갱신
 │    └ 자체 전체화면(컨테이너 기준, 오버레이 포함)
 ├─ Editor / ProductCard(탭) / LibraryDrawer(우측)
 │    핫스팟 폼 · 제품 탭 · enrich · JSON 입출력 · 라이브러리
 └─ Vite 개발 서버 플러그인 (vite.config.js) — 현재 백엔드 역할
        GET /api/videos           폴더 스캔 목록(base64 ID)
        GET /api/video/<id>       영상 스트리밍(HTTP range)
        GET /api/enrich?url=      링크 OG 메타 추출
        GET /api/serper?q=        Serper 검색(SERPER_API_KEY, 서버측)

데이터 흐름:
 편집 → Zustand 즉시 반영 → persist로 localStorage 저장
 (2차) 위 /api/* 를 Convex actions/functions 로 이전, 저장을 Convex DB로
```

**핵심 설계 포인트**
- `coords.js`(레터박스 보정)가 뷰어·에디터 **공용 핵심 로직**
- **enrich·영상 서빙은 서버측(Vite 미들웨어)에서** → Serper 키는 `.env.local`에만(프론트 비노출). 2차에 Convex action으로 이전
- 저장은 현재 localStorage(persist) → 2차 Convex로 무변경 연결(데이터 구조 유지)
- 네이버·쿠팡 상품페이지는 OG 스크래핑 차단 → **KR몰은 Serper(구글 색인) 경로 사용**

## 5. 검증 & 브레인스토밍

### 5-1. 반드시 검증할 항목
1. **좌표 정확도** — 다양한 화면비/레터박스에서 핫스팟이 제품 위 고정되는가
2. **드래그 부드러움** — Zustand 구독으로 re-render 없이 60fps 드래그되는가
3. **시간 동기화** — start~end에 맞춰 정확히 표시/숨김되는가
4. **클릭 경험** — 새 탭 이동 자연스러운가, 일시정지가 맞는가
5. **Serper enrich 정확도** — 제품명으로 올바른 정보가 채워지는가
6. **모바일 터치** — iOS/Android 44px 터치 성공률
7. **Convex 무료 한도** — 1M 호출/월·0.5GB DB 내 예상 사용량 적합한가
